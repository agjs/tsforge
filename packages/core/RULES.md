# Rules and Meta-Rules Catalog

This document lists all rules enforced by tsforge across rule packs and meta-rules.

## Rule Packs

### bullmq

Job queue patterns with BullMQ (queue options, worker lifecycle, job naming)

- **job-name-must-be-constant** [WARN]: Disallow string-literal job names in `<queue>.add(name, ...)` calls — use a constant identifier so all consumers share one source of truth.
- **job-options-must-set-attempts** [ERROR]: Every `<queue>.add(...)` must configure `attempts` (per-call or via `defaultJobOptions`); when `attempts > 1`, also require `backoff`.
- **no-blocking-concurrency-zero** [ERROR]: Disallow `new Worker(name, processor, { concurrency: <numericLiteral ≤ 0> })` — non-positive concurrency blocks job processing.
- **queue-options-must-set-removeoncomplete** [ERROR]: Every `<queue>.add(...)` must configure `removeOnComplete` (per-call or via `defaultJobOptions`) so completed jobs don't accumulate in Redis.
- **queue-options-must-set-removeonfail** [ERROR]: Every `<queue>.add(...)` must configure `removeOnFail` (per-call or via `defaultJobOptions`) so failed jobs don't accumulate in Redis.
- **worker-must-implement-close** [ERROR]: Classes that own a `new Worker(...)` instance must declare a close-equivalent method for graceful shutdown.
- **worker-must-listen-failed** [ERROR]: Every `new Worker(...)` must register listeners for required events (default `failed`) — BullMQ failures are silent unless explicitly subscribed.

### code-flow

Control flow clarity and early returns

- **no-bare-date-now** [ERROR]: Disallow direct calls to non-deterministic time/random sources (`Date.now()`, `new Date()`, `Date()`, `Math.random()`) outside an allowlisted set of utility paths. Determinism is required for snapshot tests, workflow replays, and time-travel debugging — every consumer should route through a typed util that can be faked in tests.
- **no-template-trim-empty-ternary** [ERROR]: Disallow inline `<template>.trim() === '' ? fallback : <template>.trim()` patterns. Extract to a named utility.
- **prefer-early-return** [ERROR]: Prefer guard clauses (early return) over wrapping the function body in a multi-statement `if` without an `else`.

### comment-hygiene

Meaningful comments and documentation standards

- **no-historical-comments** [ERROR]: Disallow comments that frame code relative to what it used to do or to a past incident ('Codex flagged X', 'before the fix', 'after the refactor', 'we used to', 'no longer'). Source comments must describe the current invariant; history belongs in the commit message or PR description, where it doesn't rot when the code changes again.
- **no-narration-comments** [ERROR]: Disallow narrative comments like 'Here we...', 'Now we...', 'First, we...'. These read as step-by-step prose and add no information a future reader can't get from the code itself. Often a tell that the comment was generated by an agent describing its own changes.
- **no-pr-reference-comments** [ERROR]: Disallow PR/issue references in comments. They belong in commit messages and PR descriptions — leaving them in source rots when the repo moves, the issue tracker migrates, or the numbering changes.

### drizzle

Database access patterns using Drizzle ORM (schema safety, query scoping, transaction safety)

- **account-scoped-tables-require-where** [ERROR]: Require every Drizzle query against a configured account-scoped table to filter by a scope column (accountId by default).
- **no-nested-db-transaction** [ERROR]: Forbid invoking the outer db's `.transaction(...)` method inside a transaction callback — use the callback's `tx` parameter instead to avoid deadlocks.
- **no-raw-sql-outside-allowlist** [ERROR]: Disallow drizzle-orm `sql` tagged template literals outside an allowlist of files (migrations, raw queries).
- **relations-must-cover-fks** [ERROR]: Every Drizzle table that declares a foreignKey(...) must be covered by a relations(...) call. Searches sibling `relations.ts` files by default.
- **schema-files-must-not-import-driver** [ERROR]: Disallow imports from database driver packages inside schema files. Schema files must remain driver-agnostic.
- **schema-files-must-only-export-schema** [WARN]: Restrict schema files to exporting only Drizzle schema artifacts (tables, schemas, relations, indices) and types.
- **tables-must-have-timestamps** [WARN]: Require Drizzle tables to declare standard timestamp columns (createdAt by default).
- **timestamp-must-specify-mode** [ERROR]: Require every Drizzle timestamp(...) call to explicitly set `mode: 'date'` or `mode: 'string'`.

### elysia

Elysia framework best practices and type-safety patterns

- **consistent-status-via-set** [ERROR]: Inside Elysia route handlers, set HTTP status via `set.status = N`, not by returning a `new Response(body, { status: N })`.
- **no-decorate-state-collision** [ERROR]: Disallow duplicate keys across `.decorate()` / `.state()` / `.derive()` / `.resolve()` calls on a single Elysia instance — duplicates silently overwrite and break plugin composition.
- **no-separate-model-interfaces** [WARN]: Disallow TypeScript interfaces that duplicate the shape of a runtime schema with a matching name. Use `typeof Schema.static` (or your project's equivalent) instead.
- **prefer-destructured-context** [WARN]: Prefer destructured context (`{ body, set, ... }`) over passing the entire dynamic Elysia context object into controllers/services.
- **prefer-direct-return** [WARN]: Inside Elysia route handlers, return values directly instead of wrapping them in `new Response(...)` or `Response.json(...)` — Elysia handles serialization and content-type automatically.
- **prefer-static-services** [WARN]: Discourage `new Service()` inside Elysia route handlers when the class is stateless — prefer static methods or a singleton.
- **prefer-throw-status** [WARN]: Inside Elysia route handlers, prefer `throw status(...)` over try/catch blocks that build their own Response — local catches bypass Elysia's typed onError pipeline.
- **require-hooks-before-routes** [ERROR]: Elysia hooks (onError, onBeforeHandle, etc.) must register before any route methods on the same instance — top-down waterfall semantics mean a hook registered after a route does not apply to it.
- **require-plugin-name** [ERROR]: Exported Elysia plugin instances must declare `new Elysia({ name: '...' })` so the runtime can deduplicate plugin re-imports.

### env-access

Safe environment variable access patterns (validation and typing)

- **no-direct-process-env** [ERROR]: Disallow direct `process.env` access — force every consumer through a typed, boot-validated singleton.
- **no-process-exit** [ERROR]: Disallow `process.exit()` outside the centralized shutdown and CLI entrypoints — forces graceful teardown through the error-handlers module.

### i18n-keys

Internationalization key management and translation patterns

- **static-translation-key-exists** [ERROR]: Static string passed to `t("...")` or `i18n.t("...")` must exist as a leaf path in the canonical locale JSON.

### jwt-cookies

Secure JWT and cookie handling patterns

- **auth-cookie-must-be-httponly** [ERROR]: Auth-cookie writes must set `httpOnly: true` (or spread a trusted cookie-config helper). JS-readable session cookies leak via XSS.
- **auth-cookie-must-be-secure-in-prod** [ERROR]: Auth-cookie writes must set `secure:` to `true` or an env-derived expression (anything non-literal). Cookies leak over HTTP without it.
- **bcrypt-rounds-min** [ERROR]: Disallow `bcrypt.hash` / `bcrypt.hashSync` calls with a numeric-literal rounds value below the configured minimum (default 10).

### module-boundaries

Module boundary hygiene: keep the test/production and source/build-output boundaries clean so the dependency graph stays sound.

- **no-import-build-output** [ERROR]: Disallow importing from build/output directories within the project. Source must import source, not compiled artifacts, to avoid stale-code drift and broken module boundaries.
- **no-import-test-from-source** [ERROR]: Disallow production/source files from importing test files. Tests may depend on source, never the reverse — test code must not ship in the production graph.

### oauth-security

OAuth and OpenID patterns and security considerations

- **pkce-required-for-oidc** [ERROR]: OIDC providers must use PKCE: `buildAuthorizationURL` must call `generateCodeVerifier()` and pass it to `createAuthorizationURL`.
- **state-must-be-redis-backed** [ERROR]: OAuth state must be persisted to Redis and not stuffed into a cookie. Cookie-backed state lets attackers replay forged state across sessions.
- **state-ttl-bounded** [ERROR]: OAuth state writes to Redis must use a short TTL — long-lived state widens the replay window.

### react-component-architecture

Component structure, composition, and file organization for React

- **component-folder-structure** [ERROR]: Enforce required sibling files in component folders (hooks, types, stories, test, index)
- **forwardref-display-name** [ERROR]: forwardRef components must have displayName set
- **index-must-reexport-default** [ERROR]: index.ts in component folders must re-export the component default export and types
- **max-hooks-per-file** [WARN]: Flag query/hook modules that export more than N hooks. Same-kind modules pass the single-semantic-module rule but still grow into god files; this rule sets a hard ceiling so the split conversation happens early.
- **no-cross-feature-imports** [ERROR]: Prevent imports across different features
- **no-inline-jsx-functions** [WARN]: Disallow inline function expressions in JSX attributes

### structured-logging

Structured logging best practices: PII masking, error handling, and event field requirements

- **mask-pii-fields** [ERROR]: Disallow unmasked PII (email, phone, password, token, ...) in structured-logger payloads — the #1 way data leaks quietly.
- **no-error-stringify** [ERROR]: Disallow stringifying errors with `String(error)` / `${error}` / `error.toString()` — strips the cause chain. Use a configured extractor instead.
- **require-event-field** [ERROR]: Require structured logger calls to include an `event` field in their payload, so log searches in ELK/Datadog/Loki don't fall back to substring match.

### tanstack-query

Patterns for data fetching with TanStack Query

- **prefix-query-key-must-use-set-queries-data** [ERROR]: When a hook uses `queryKey: [...prefix, extra]`, do not call `setQueryData(prefix, …)`, `cancelQueries({ queryKey: prefix })`, etc. — those only touch one cache entry. Use `setQueriesData({ queryKey: prefix }, …)` and matcher-style `cancelQueries` / `invalidateQueries` so every variant is covered.

### test-conventions

Testing patterns and file structure for vitest, jest, or Bun tests

- **no-focused-tests** [ERROR]: Disallow focused tests (`test.only`, `it.only`, `fdescribe`, ...) — the canonical 'I forgot to remove this before committing' leak.
- **test-file-mirrors-source** [ERROR]: Every test file under `tests/` must mirror a source file under `src/`. Catches orphaned tests left behind after refactors and renames.

## Meta-Rules

Meta-rules enforce project structure and configuration invariants that ESLint cannot express.

### supply-chain

- **no-overlapping-libs** [WARN]: package.json must not list forbidden overlapping library pairs (e.g. axios + node-fetch).
- **package-exact-deps** [WARN]: dependencies and devDependencies must use exact versions (no ^ or ~ ranges).

### config

- **tsconfig-paths-exist** [ERROR]: Literal tsconfig include/files entries must point to files that exist on disk (glob patterns exempt).
- **tsconfig-strict** [WARN]: tsconfig.json should enable strict mode for type safety (strict: true or all individual strict flags).

### source-text

- **no-eslint-disable-comments** [ERROR]: Source files must not contain inline eslint-disable directives.
- **no-ts-suppressions** [ERROR]: TypeScript suppression comments (@ts-ignore, @ts-nocheck, @ts-expect-error) are not allowed.

### testing

- **test-sibling-required** [WARN]: Logic modules (*.service.ts, *.utils.ts, etc.) should have a co-located *.test.ts sibling.

### ci

- **workflow-actions-pinned** [WARN]: GitHub Actions `uses:` directives must pin to a version tag (v1, v2, etc.) or full SHA, not floating refs like @main.
- **workflow-runner-pinned** [WARN]: Workflows must pin runner images to an explicit OS version (e.g. ubuntu-24.04) instead of floating *-latest labels.
- **workflow-timeout-required** [WARN]: GitHub Actions jobs require an explicit timeout-minutes (reusable-workflow calls exempt).
