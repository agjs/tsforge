## What it is

The seam the model plugs into, behind a small `Provider` interface:

```ts
interface Provider {
  complete(messages: ChatMessage[], opts?): Promise<ModelResponse>; // { content, toolCalls }
}
```

`OpenAICompatibleProvider` hits `POST {baseUrl}/chat/completions` — the API that **Ollama, vLLM, and llama.cpp all expose** for a local Qwen3.6. It parses the response into `content` plus decoded `toolCalls` (`{ name, arguments }`), so the rest of the harness never touches HTTP or vendor JSON.

## Why provider-agnostic + injectable fetch

- **Agnostic:** swap `baseUrl`/`model` to point at any local server; no code change.
- **Injectable `fetch`:** the whole adapter is unit-tested deterministically against canned responses — no GPU, no flakiness.

## Now built

Streaming (SSE → `onToken`, with a `StreamGuard` that aborts repetition loops), the `tools` schema in the request (with salvage for malformed tool-call syntax), connection retries, and per-request timeout/cancellation are all implemented. The provider also accepts object-valued `tool_call.function.arguments` (some local servers emit an object, not a JSON string) and surfaces the response body in HTTP errors. The tool-using loop that drives this provider lives in `loop/turn.ts` (shared by `runTask` and the interactive `Session`).
