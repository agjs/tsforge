:::caution[Legacy path — being retired]
This synthesizes a Vite/React app from tsforge's own templates. It is superseded by
[Greenfield scaffolding](/scaffold/boringstack/), which stands up the proven
BoringStack template instead of inventing a stack. `--web` still works today but is
slated for removal once the eval paths migrate off it. For new projects, prefer
`tsforge scaffold`.
:::

Use this when you want tsforge to **create a new browser app from scratch**, not when you are editing an existing codebase.

Instead of letting the model invent folder structure and config, tsforge materializes a known-good Vite stack, installs dependencies, and switches to a stricter **web gate** so "done" means the app actually builds and renders.

## Starting a web session

```bash
tsforge --web --dir ./my-app
```

Describe the app in your first message. Add `--plan` if you want a read-only design phase before files are edited ([Plan mode](/cli/plan-mode/)).

## Agent tools (what the model calls)

### scaffold_web

Run **once** at the start of a greenfield UI build.

| Framework | What you get |
| --- | --- |
| `react` | Vite + React + shadcn-style UI + TanStack Router + TanStack Query |
| `vanilla` | Vite + TypeScript + Tailwind |

After this runs: template files are written, `bun install` runs, the session gate switches to the web ladder, and stack-specific prompt guidance is injected.

Do not use this on CLI-only projects or existing repos you are patching.

### scaffold_ui

Generates themed UI primitives under `src/components/ui/` and design tokens in `src/index.css`.

Themes: `minimal`, `warm`, `futuristic`. Primitives include button, card, input, table, `skeleton`, and layout blocks (app-shell, page-header, empty-state, etc.).

Call once with everything the app needs. Do not hand-roll base components the scaffold already provides.

**Loading states are skeletons.** Every `isLoading`/`isPending` branch renders a `<Skeleton/>` shaped like the content it stands in for (rows, cards, a heading line) — never a spinner and never `"Loading…"` text. The gate enforces this: the [`no-loading-text-use-skeleton`](/guardrails/rule-packs/#react-component-architecture) rule rejects loading-text nodes.

```tsx
if (isLoading) {
  return <Skeleton className="h-9 w-full" />;
}
```

The `table` primitive is **column-driven** — it _is_ the table, not a base for per-feature wrappers. Pass typed rows and a column spec; there is no `DealsTable`/`UsersTable`:

```tsx
const dealColumns: readonly IColumn<IDeal>[] = [
  { header: "Name", cell: (d) => d.name },
  { header: "Value", cell: (d) => formatCurrency(d.value) },
];

<Table columns={dealColumns} data={deals} rowKey={(d) => d.id} />;
```

## Project layout (views)

Scaffolded apps follow a **views** layout, and the [`react-component-architecture`](/guardrails/rule-packs/#react-component-architecture) rules enforce it at the gate. Each screen/feature is a folder under `src/views/`:

```
src/views/<Feature>/
  index.tsx              the view — the composition root
  components/<X>.tsx      feature components (one per file)
  <feature>.types.ts     the feature's interfaces (I-prefixed)
  <feature>.constants.ts  its label maps, column specs, typed seed data
  <feature>.hooks.ts     custom hooks (data fetching, derived state) — if needed
src/components/ui/         shared, feature-agnostic primitives (scaffold_ui)
src/lib/utils.ts           cn() class-name helper (editable)
src/routes/<feature>.tsx   thin TanStack route shell → renders the view
```

Two hard rules the gate enforces (`component-file-purity`, `component-folder-structure`):

- A component `.tsx` contains **only imports and the component**. Types go to `<feature>.types.ts`, constants to `<feature>.constants.ts`, hooks to `<feature>.hooks.ts`, pure helpers to `src/lib` — never inline above a component.
- **No gratuitous wrappers.** Compose the shared primitives directly in the view; only create a `components/<X>.tsx` when a piece has real local state, is reused, or is large enough to stand alone.

**What's read-only.** Only the generated TanStack route tree (`*.gen.ts`) is off-limits to the model (it's regenerated by the build, so edits are pointless) — the edit/create tools reject writes to it. Everything else the scaffold lays down, including `src/lib/utils.ts` and the shadcn primitives in `src/components/ui/`, is clean, strict, and **editable like any other file**. See [Vendored & read-only scope](/edit/engine/#vendored--read-only-scope).

## Data layer

The scaffold ships **no data/SDK layer** — you write your own, and the gate holds it to the same strictness as any code (no `as`, no `eslint-disable`). Two cases:

**Local / demo data** (the common case): a typed constant in `<feature>.constants.ts`.

```ts
export const SEED_DEALS = [{ id: "1", title: "Acme", amount: 1200 }] satisfies readonly IDeal[];
```

Plain literals, no casts — the `satisfies` (or a `: readonly IDeal[]` annotation) is the validation. Render it directly.

**Async / fetch:** `@tanstack/react-query` is installed and `QueryClientProvider` is wired in `src/main.tsx`. Write your own hook in `<feature>.hooks.ts`:

```ts
// useQuery/useMutation wrapping fetch — narrow the unknown response, never `as`-cast it.
export function useDeals() {
  return useQuery({ queryKey: ["deals"], queryFn: async (): Promise<readonly IDeal[]> => { /* … */ } });
}
```

Keep hooks in `<feature>.hooks.ts`, never in a component body (`no-state-in-component-body`).

### scaffold_routes

Creates TanStack file routes as stubs in one shot, for example `["/", "/accounts", "/accounts/$accountId"]`. Each stub compiles; you fill in real UI later.

### add_dependency

Wrapper around `bun add` for missing npm packages (`date-fns`, `zod@3`, etc.).

## What "done" means for web apps

After scaffolding, the gate runs a longer pipeline roughly equivalent to:

```
vite build → tsc → eslint → stub-check → prettier → browser smoke
```

| Step | Catches |
| --- | --- |
| Vite build | broken imports, JSX, Tailwind |
| tsc | type errors |
| ESLint | web-specific idioms |
| stub-check | route placeholders left unfilled |
| prettier | formatting drift |
| browser smoke | blank page, console errors |

During plan mode's design phase, only the lighter subset runs (types + lint, no full build). See [Plan mode](/cli/plan-mode/).
