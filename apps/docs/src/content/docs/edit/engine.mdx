The model changes your codebase through three tools. All of them can trigger immediate type feedback after a successful write ([Write diagnostics](/uplift/write-diagnostics/)).

## edit (find and replace)

The model provides an exact `oldString` and `newString` inside a file.

| Outcome | Meaning |
| --- | --- |
| 1 match | file updated |
| 0 matches | snippet not found |
| 2+ matches | ambiguous; model must add more context |

Best when the model has read the full file and can quote a unique snippet.

## edit_lines (line ranges)

Line-number edits anchored to a content hash from the last read. Safer when the file might have changed between read and write.

→ [Hashline edits](/uplift/hashline/)

## create (new file)

Writes a new file only. Refuses to overwrite an existing path. Creates parent directories as needed.

## Vendored & read-only scope

Some paths are **vendored** — tested, already-type-correct harness files. Both `edit` and `create` reject any write to them, regardless of the session's editable scope (`--files`, spec `files:`):

| Path | Why it's read-only |
| --- | --- |
| `src/lib/**` | the scaffold's SDK (`api`, `use-resource`, `result`, `sort`, …) |
| `src/components/ui/**` | the `scaffold_ui` primitives |
| `src/mocks/db.ts`, `src/mocks/browser.ts` | the MSW mock machinery (you edit `src/mocks/handlers.ts`, not these) |
| `**/*.gen.ts` | code generation output (e.g. TanStack's route tree) |

This exists to stop a failure mode: a model that "fixes" the generic SDK types it can never satisfy — and, with [eslint-disable / `@ts-*` suppressions banned](/guardrails/meta-rules/), has no escape — loops to the turn cap. The rejection message redirects it: a type error involving a vendored file is a wrong **call site**, not a library bug.
