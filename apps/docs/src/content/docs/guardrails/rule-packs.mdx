---
title: Rule packs
description: Stack-specific ESLint rules tsforge runs during the gate.
---

When the gate runs ESLint, it does not use a generic preset. It uses **rule packs**: groups of rules keyed to the libraries in your project.

If you use Drizzle, tsforge applies Drizzle-specific query rules. If you use React, it enforces component folder layout and JSX conventions. [Stack detection](/guardrails/stack-detection/) turns packs on from `package.json`. You can override in [tsforge.config.json](/guardrails/config/).

Packs apply on every gate check, whether tsforge is editing an existing repo or scaffolding a new one.

## How a pack gets enabled

1. tsforge detects your stack from dependencies
2. optional `tsforge.config.json` adds or removes packs
3. the gate runs all enabled pack rules as errors by default

| `comment-hygiene` | Comment Hygiene | yes |

| `jwt-cookies` | JWT & Cookies | yes |
| `oauth-security` | OAuth Security | yes |
| `i18n-keys` | i18n Keys | yes |

"Detection only" means tsforge knows the stack label but does not ship extra rules for it yet.

Every implemented rule with fix text: [Rule catalog](/reference/rules-catalog/).

## Changing severity

Pack rules default to **error** (gate fails). Set `"warn"` or `"off"` per rule in [tsforge.config.json](/guardrails/config/).
