---
title: tsforge.config.json
description: Optional project file to force stacks, include or exclude rule packs, and tune severities.
---

You do not need this file to use tsforge. Stack detection works from `package.json` alone.

Add **`tsforge.config.json`** at your repo root when you want to override what tsforge detected: force an Elysia stack, disable a pack you do not use, or downgrade a noisy rule to a warning.

## Fields

| Field | Type | Purpose |
| --- | --- | --- |
| `stack` | string | Force-enable a stack and its packs |
| `packs.include` | string[] | Add packs after detection |
| `packs.exclude` | string[] | Remove packs after detection |
| `rules` | object | Per-rule severity: `"error"`, `"warn"`, or `"off"` |

Resolution order: detect from the repo → apply `stack` → apply `include` → apply `exclude` → dedupe.

If the file is missing, tsforge uses detection only. If JSON is invalid, tsforge warns on stderr and continues with an empty config.

## Rule names

Bare names and `tsforge/`-prefixed names both work:

```json
{
  "no-direct-process-env": "error",
  "tsforge/prefer-early-return": "warn",
  "no-historical-comments": "off"
}
```

## Example

```json
{
  "stack": "elysia",
  "packs": {
    "include": ["structured-logging"],
    "exclude": ["bullmq"]
  },
  "rules": {
    "no-direct-process-env": "error",
    "tsforge/prefer-early-return": "warn",
    "no-historical-comments": "off"
  }
}
```

This project is treated as Elysia, keeps structured-logging rules, skips BullMQ rules, and softens one comment rule.
