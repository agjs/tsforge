## What it does

`modelAgent(provider)` returns an `IAgent`. Each cycle it:

1. **Reads the declared files** (`task.files`) into context — the model can't write a matching `oldString` for a file it can't see.
2. Sends the model the files + acceptance command + current failures, advertising the **`edit` tool** (`{ file, oldString, newString }`).
3. Applies each `edit` tool call through the [edit engine](/edit/engine/) (which enforces the exact/unique match). Non-edit or malformed calls are ignored.

## The live eval that shaped it

Run `bun run packages/core/scripts/eval-sum.ts` against the local model. It found a real weakness, then confirmed the fix:

| Setup | Result |
| --- | --- |
| Model given the file + test directly | Emitted a **perfect** `edit` (exact, unique `oldString`) |
| ModelAgent **blind** (errors only, no file) | `stuck/stalled` — couldn't match `oldString` |
| ModelAgent **with file context** (the fix) | `done` in **1 cycle**, file correctly rewritten |

This is the method: the real model is the weakness-finder. Blind-vs-context wasn't a guess — the model showed us.

## Deliberately absent (next)

Glob expansion for `task.files` (currently literal paths), scope/drift enforcement on edits, feeding the error-set **diff** (not the full set), multi-file edits, and **MCP tools** (e.g. context7) alongside `edit`.
