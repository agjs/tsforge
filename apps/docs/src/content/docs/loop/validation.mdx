## What it adds over the skeleton

The skeleton's gate was a boolean. Now a failing gate produces a **structured error set**, and `runTask` runs a real **REPAIR loop** that feeds the model the standing errors each cycle.

- **Error set** — `ErrorItem { key, file?, line?, rule?, message }`. A failing gate **always** has ≥1 error (empty output still yields one).
- **Diff** — `diffErrorSets` → `{ fixed, introduced, remaining }`; `shrank` = the set got smaller (progress).
- **Loop** — `RED → (EDIT → VALIDATE)*`. Stops at: `done` (gate green), `stuck/stalled` (no shrink for **N=3** cycles), or `stuck/cap` (**12** cycles).
- **Parsers** — `parseTsc`, `parseEslintJson` (carries custom plugin rule ids), and `genericErrors` (fallback).

## Gate composition

| Layer | Source | Examples |
| --- | --- | --- |
| TypeScript | `tsc --noEmit` | TS2322, TS6133 |
| ESLint packs | [rule packs](/guardrails/rule-packs/) | `@tsforge/no-direct-process-env` |
| Meta-rules | [meta-rules](/guardrails/meta-rules/) | `test-sibling-required`, `package-exact-deps` |
| Format + tests | `prettier --check`, `bun test` | format drift, test failures |

Stack detection picks packs; [tsforge.config.json](/guardrails/config/) overrides them.

## Pieces

| Module | Does |
| --- | --- |
| `validate/errors.ts` | `ErrorItem`/`ErrorSet`, `diffErrorSets`, `shrank` |
| `validate/parse.ts` | `parseTsc`, `parseEslintJson`, `genericErrors`, `parserFor` |
| `validate/validate.ts` | run gate → `{ passed, errors, output }` (≥1 error on failure) |
| `loop/run.ts` | REPAIR loop + stall (N=3) + hard cap (12) |
| `detect-gate.ts` | assemble strict ESLint config from enabled packs |

## Deliberately absent (next)

Tiered/scoped checks per edit, wiring the loop's `stuck` into **escalate → notify**, and surfacing the error-set *diff* (not just the full set) to the agent.
